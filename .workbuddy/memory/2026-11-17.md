## 分析 pkg/htwheel/（分层时间轮调度器）
- 组成部分：Task、WorkerPool（8 worker + 1024 缓冲）、bucket、TimingWheel（tick 100ms / size 512，多级 overflow）、Scheduler 门面。
- 用法：Schedule/Update/Get/TTL/Cancel/Stop；同 id 覆盖语义；execTime 传的是 task.expire（计划时间）而非真实执行时间。
- 发现的缺陷（未修改代码，仅分析）：
  1. 并发安全：add/onTick/cancel 在 Start 的单一 goroutine 内串行，但 Get/TTL/Update 直接同步读 taskIndex/buckets，无锁 → 并发 map 读写 panic。
  2. overflow 作为独立 TimingWheel 各自 Start goroutine，drainTo/overflow.add 跨 goroutine 调用且无锁 → 竞态。
  3. WorkerPool.Stop 与 Submit 并发：close(ch) 时若仍 Submit 会 panic；wg.Add 与 wg.Wait 竞态。
  4. Scheduler.Stop 只关闭 stopCh，不等待 goroutine 退出，不关闭 wp.ch；overflow 层未 Stop。
  5. Update 只查第一层 taskIndex，位于 overflow 的任务无法 Get/Update/Cancel。
  6. drainTo 未删除 overflow 的 taskIndex，长任务索引残留。
  7. add 中 delay<0（已过期）视为立即执行；onTick 中未到期任务反复 add 可能死循环重排。
  8. t.expire/t.fn 无显式锁，依赖单 goroutine 假设被 Get 破坏。
- 测试 TestHtWheel 只是 smoke test，无并发用例、无 -race 验证。

## 已按建议修复 pkg/htwheel/（重构）
- 并发模型改为「单一驱动 goroutine 独占全部状态」：所有层的时间轮（wheel，无 goroutine）与全局索引 index 只在该协程内读写；Get/TTL 走 getCh+resp、Update 走 updCh+resp，彻底消除并发 map 读写。
- 分层改为单驱动推进：advance(0) 每 tick 推进，某层转满一圈才让上一层前进一格；删除 overflow 子轮与跨层直接调用。
- 全局索引跨层可见：长延时任务在任意层都能 Get/TTL/Update/Cancel。
- place 用向上取整（ceil），修复原实现「delay<tick 立即执行」导致的提前触发；到期任务 delay<=0 立即提交。
- WorkerPool：mu 保护 closed+wg.Add+发送，Stop 用 sync.Once，先置 closed 再 wg.Wait 再 close(ch)；worker 内 recover 防单任务 panic 拖垮进程。
- Stop 幂等：stopped 原子标志 + close(stopCh) + 等 doneCh 退出 + wp.Stop()；停止后 API 返回 false。
- 边界：size 最小 2（否则单层永远装不下）；addLevel 检测 tick 溢出并用最粗层取模兜底，避免无限建层。
- API 变化：新增 Option（WithTick/WithSize/WithWorkers），Schedule/Cancel 增加 bool 返回；移除导出的 TimingWheel/NewTimingWheel（无外部引用）；Task.Expire 改指针接收者避免复制 atomic 字段。
- 测试重写为 10 个用例（覆盖/跨层/取消/并发/幂等/远期），`go test -race -count=3` 全绿。

## 新增 htwheel 持久化能力
- 新增文件：persist.go（Record / Store 接口 / Handler / PersistOption / PersistentScheduler）、store.go（MemoryStore、FileStore 原子重写）、persist_test.go。
- 设计要点：闭包不可序列化，存元数据 Record{ID,Expire,Name,Payload}，执行时按 Name 查 Handler 注册表。
- Store 接口仅 4 个方法：Put / Get / Delete / Scan(before,limit)，Scan 返回 expire<=before 且按 expire 升序，便于用 DB 索引。
- PersistentScheduler：Schedule/Update/Cancel 写存储；后台每 PollInterval 执行 Scan(now+Lookahead) 预热未加载任务；Schedule 成功即预热，不必等轮询。
- 一致性与语义：存储为 source of truth；fire 前二次读存储，取消/改期则跳过；成功后 Delete；at-least-once（panic 或删除前崩溃会重试）；处理器缺失保留记录并回调 OnError，注册后重试；running 标记防止慢 handler 期间被轮询重复预热。
- 测试：7 个持久化用例（调度执行、外部插入、取消、改期、文件恢复、缺失处理器重试、慢任务防重），go test -race 全绿。
