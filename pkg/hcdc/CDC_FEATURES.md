# CDC 功能清单与验收标准

本清单用于规划和验收从 MySQL / MariaDB 到 Doris 的 CDC。每条主流水线同步一个源库，同一源实例可以管理多个库，多个实例可以共享一个 Doris 集群。最小可用版本完成可恢复的全量与增量同步。生产版本补齐结构演进、故障处置、监控和容量管理。

当前 `pkg/hcdc` 的源表范围是具有稳定主键的 InnoDB 表，使用 ROW/FULL Binlog。无主键、生成列及可能遗漏行事件的级联外键写入会在预检时被拒绝。

## 1. 最小可用功能

| 功能 | 实现要求 | 通过条件 |
| --- | --- | --- |
| 源端预检 | 验证连接和复制权限、唯一复制客户端 `ServerID`、源成员身份、可用 Binlog，以及 `binlog_format=ROW` 和 `binlog_row_image=FULL`。在启动时校验选中表的引擎、主键和列定义。 | MySQL 和 MariaDB 均可建立复制连接。源权限不足、配置不匹配或表结构超出支持范围时，返回可定位的错误。 |
| 选库、选表与目标映射 | 全量和增量共用同一套过滤规则，排除规则优先。固定每条流的源身份、代次、目标库及列映射。多个实例共享 Doris 时检测名称冲突，按 `SchemaPrefix` 生成目标库名。 | 排除表在全量和增量中均无业务写入。同名源库可用 `{InstanceId}` 隔离，冲突在启动前被拒绝。 |
| 元数据和类型转换 | 读取源物理列序、数据类型、字符集和主键，按目标模型编码。区分 NULL、空字符串与缺失列，处理 DECIMAL、无符号整数、时间、JSON、二进制及 UTF-8。 | 用边界值逐字段比较源端和目标端，导入过滤行数为零。出现超限值或无法转换的类型时，错误包含库表、列及位点。 |
| 一致性全量快照 | 在同一一致性视图中扫描选中表并记录对应 Binlog 位点。按稳定主键顺序读取，分批导入并核对表结构、行数和空表。确认全部快照批次后发布序号 `0` 基线。 | 向正在扫描的表并发写入，快照结果对应同一基准点。后续增量接续后，按主键核对完整数据。 |
| 增量采集和事务边界 | 从基线或持久位点订阅 Binlog，识别事务提交、回滚与 DDL。每次提交输出完整的有序记录。支持 INSERT、UPDATE、DELETE 和主键修改，主键修改生成旧键删除与新键写入。 | 同一事务覆盖多表、同键多次修改和主键变更。回滚不产生目标业务写入，旧主键记录被删除，Binlog 轮转后仍可继续消费。 |
| 持久缓冲与顺序交付 | 按源提交顺序保存事务、游标、依赖的结构版本和不可变导入计划。缓冲记录带序号和校验和，恢复时核对流身份与记录连续性。 | A 表的早期记录仍待交付时，B 表的后续记录无法推进该源的交付检查点。损坏、缺号或身份不符时停在可核对的位点。 |
| Doris 导入与回执核对 | 将事务按目标表和分片编码，通过 Stream Load 导入。相同批次重试使用原 Label 和内容。用回执、事务状态或审计证据核对导入结果、载荷校验和、实际行数和过滤行数。 | 模拟导入成功但响应丢失，恢复时能核对原批次。目标结果未知或证据冲突时，保留原计划并阻塞该源。 |
| 检查点与断点续传 | 按连续已确认前缀推进检查点。当前记录的所有批次和 DDL 均已确认后，持久化并读回检查点，再回收可清理的缓冲。网络中断时从可证明的持久进度恢复。 | 停止 CDC 后继续写源并轮转 Binlog。使用原卷重启后逐主键对账一致。所需 Binlog 已清理或本地记录缺失时安全阻塞。 |

### 必须守住的位点约束

- **已读取**记录采集端已经观测到的源进度，用于诊断。
- **已落盘**只覆盖完整、按序保存的事务或结构记录，使用原卷重启时可据此续订采集。
- **已交付**只覆盖目标已确认且检查点可读回的连续记录。始终满足 **已交付 ≤ 已落盘 ≤ 已读取**。
- 源事务的多个 Doris 批次可以先后对读者可见。若业务要求跨表原子可见，还需单独设计消费者发布边界。

## 2. 生产必需功能

| 功能 | 实现要求 | 通过条件 |
| --- | --- | --- |
| 首次全量崩溃恢复 | 持久化初始表清单，在首次业务导入前封存全部编码批次和基准游标。封存前中断重取快照。封存后核对原 Label，按证据补发。Doris 序号 `0` 已提交时核对原基线并补齐本地完成标记。 | 在封存前、导入中、序号 `0` 已提交且本地完成标记尚未写入时分别强杀。原卷重启保留库表，快照和增量逐主键一致，并核对批次回执。 |
| 结构版本与 DDL 屏障 | 按源游标保留结构版本。DDL 等待前序数据已交付，目标变更确认并保存新版本后开放后续 DML。区分自动执行、人工审批、需要新代次的变更。 | 分别验证兼容加列、可审批操作和不可在原代次执行的操作。错误审批 ID 被拒绝，进程重启后可以核对原屏障及审批状态。 |
| 单写保护与故障隔离 | 对每条流水线的缓冲目录加排他锁，并在 Doris 核对目标库和流的写入声明。跨卷接管前隔离旧写者并确认在途请求。每条源流水线独立管理缓冲、进度和失败。 | 同目标的第二个进程启动被拒绝。一条源暂停或受 DDL 阻塞时，另一条源仍能推进。 |
| 背压、容量和清理 | 对待交付数据、单笔事务、原始事件和批次设定上限。磁盘预算覆盖全量封存、事务暂存、增量积压和回收余量。核对 Binlog 和 Doris 回执的保留窗口，按恢复需求清理控制表历史。 | 用预计峰值、宽行和 Doris 停机压测，记录吞吐、p95 延迟、积压峰值、盘占用和重启追平时间。容量到阈值时触发背压，恢复后继续交付。 |
| 运行控制和配置校验 | 按源启动、暂停、恢复、停止、审批和优雅关闭。使用 `Config.Validate` 校验 YAML，使用 `Equal` 判断配置变化。同代次更换连接配置失败时可恢复原配置与检查点。 | 停止、限时关闭、错误凭据、超时及重复更新均有明确结果。恢复后原位点可续传，其他源持续运行。 |
| 监控、日志和审计 | 提供单源运行阶段、三个水位、积压字节数、背压、错误和 DDL 状态。通过 SDK 查询或订阅回调。宿主补充端到端延迟、吞吐、最早积压年龄及告警，负责控制操作的鉴权与审计。使用 `pkg/herror` 保留错误链，使用 `pkg/hlog` 记录源 ID、代次、游标和 Label，并遮盖连接凭据。 | 按源定位故障发生在采集、缓冲、DDL 或交付阶段。告警可关联到当前检查点，操作有可追溯记录。 |
| 数据对账与修复 | 按主键区间比较源与目标的行数、键集合和规范化字段摘要，差异时逐行核对。建立安全重建路径，明确哪些故障可在原代次恢复，哪些需要新代次和空目标。 | 制造漏行、错值或证据缺失，验收可发现并定位。按原卷恢复或新代次重建流程重新对账后再放行。 |

### DDL 的实现范围

| 类型 | `pkg/hcdc` 处理方式 |
| --- | --- |
| 兼容的可空加列 | 自动交付，目标结构确认后推进屏障。 |
| `TRUNCATE`、单个受支持的非键值列删除或重命名、保持 Doris 投影的无损整数扩宽 | 审批绑定具体代次和游标。核对目标结果后恢复交付。 |
| 改主键定义、表改名、实际 Doris 类型变化及未支持的组合 DDL | 保留屏障，经新代次全量重建后重新对账。 |

## 3. 按业务需求补齐的扩展

| 能力 | 触发条件与实现要点 |
| --- | --- |
| GTID 跨主续传 | 源有主从或故障切换要求时，在建立新代次时启用 GTID。切换前隔离旧主并核对新主复制谱系、已落盘 GTID 和所需历史。历史缺失的候选安全阻塞。选主和写入围栏由部署侧管理。 |
| 自动接入新库和新表 | 需要动态创建 Schema 时，后台发现匹配的库表并创建 Doris 目标。新库建立自己的基线，已有库中新表使用独立检查点。验证新增对象初始化或重启时，原有库表持续推进。 |
| 影子同步和消费者路由 | 生产读流量需要灰度或回退时，在同一确认位点校验旧目标和新目标。持久化逐源路由修订，拒绝过期证据，通过读回核对结果未知的发布请求。切换和回退均验证消费者重启后的实际读目标。 |
| 特殊类型和业务规则 | 按实际源数据支持 `CustomType=Bitmap32`、`CustomType=Bitmap64` 等声明。零日期默认阻塞，`ZeroDatePolicy: epoch` 映射为 `1970-01-01` 并统计受影响行数。转换策略变化需核对代次和历史数据。 |
| 并行全量和批次调优 | 当单源初始化或追平超过预算时，按主键区间拆分快照并限制源端与 Doris 并发。按普通行、宽行和多源分别测吞吐，任何并发策略都要保住同一一致性视图和连续交付前缀。 |

## 4. 实施和验收顺序

1. **先实现正确的同步链路**。用 MySQL 和 MariaDB 各跑一轮一致性全量、增删改、主键修改和 Binlog 轮转后的续传。检查空表、NULL、宽行和字段精度。
2. **再验证故障恢复**。覆盖首次全量的三个强杀窗口、Doris 响应丢失、缓冲损坏和 Binlog 缺失。除最终行内容之外，核对原 Label、回执数量和检查点推进顺序。
3. **完成生产放行**。验证 DDL、暂停和恢复、容量背压及多源隔离。按实际业务峰值确定每源吞吐、延迟、磁盘和日志保留预算。
4. **按部署场景补齐扩展**。有主从时演练 GTID 切主，有在线消费者时演练影子对账、逐源发布和回退。有动态建库建表需求时，验证自动接入后的全量、增量和续传。

当前实现及实库记录见 [重构设计与测试入口](REFACTOR_DESIGN.md#64-验证真实链路和-ddl-恢复)。上线前的预算、写入围栏和恢复步骤见 [生产手册](PRODUCTION_RUNBOOK.md)。配置和启停接口见 [监控 SDK](monitor/README.md)。
